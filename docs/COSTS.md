# Zero-cost deployment policy

Use the Cloudflare **Workers Free plan** for this project's zero-cost deployment. Do not upgrade the account, enable a paid service, or accept usage-based overage billing to set up OAuth. Verify the actual deployment account's product plans and usage before provisioning or enabling remote OAuth. An account name, a namespace binding, or a local test is not evidence of its billing plan. If the account cannot be verified, leave OAuth unconfigured and report that limitation.

OAuth uses the existing Worker and a Workers KV namespace, plus existing D1 audit storage. It needs no paid identity provider, Durable Object, or central orangeCMS service. The maintained OAuth library is MIT licensed. Local tests use isolated local D1/KV/R2 and do not provision remote resources.

Cloudflare currently includes these KV limits on Workers Free: 100,000 key reads per day, 1,000 writes per day, 1,000 deletes per day, 1,000 list requests per day, and 1 GB stored. These are shared account allowances, not a promise of a number of logins. A login/refresh can perform multiple operations. Operations beyond Free-plan limits fail rather than incur overage charges. Paid-plan KV can incur overages; an included allowance on a paid account does not guarantee zero cost. Verify current [KV pricing](https://developers.cloudflare.com/kv/platform/pricing/) and [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) before changing production resources.

The existing CMS also uses D1 and R2. Their product limits and billing are separate. In particular, R2's free allowance is not an unlimited, hard-capped free storage plan; excess storage or operations can cost money. A Workers Free plan alone does not guarantee that an entire existing Cloudflare account has no charges. Verify [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [R2 pricing](https://developers.cloudflare.com/r2/pricing/), and any existing Access, email, domain, or build subscriptions and usage before claiming a zero-cost production deployment. Do not silently enable paid overages to keep a site available.

Without an `OAUTH_KV` binding, OAuth discovery and the authenticated MCP endpoint return 503. Existing website behavior, public MCP, and API tokens remain available. This is the safe default until the account and deployment configuration are verified.
